# 01. AI Emonjj 产品设计与技术规格

**版本**：v0.1 MVP  
**日期**：2026-10-03  
**产品形态**：部署在博客子域名的免费 Web 应用  
**核心定位**：用户上传人物图片，系统识别人脸与基础表情，自动推荐并添加 emonjj，用户可以单独或批量替换 emonjj，最后导出图片。

## 1. 产品目标

AI Emonjj 是一个轻量、低门槛的群像图片表情贴纸工具。它优先使用固定 emonjj 素材保证速度和稳定性，同时为后续接入 AI 生成 emonjj 保留接口。

首版必须完成以下闭环：

1. 打开博客子域名即可使用，无需登录。
2. 上传一张群像图片并显示预览。
3. 检测图片中的多张人脸。
4. 为每张人脸估计一个基础表情类别。
5. 一键为所有人脸匹配并添加 emonjj。
6. 点击单个人脸后替换其 emonjj、旋转、缩放或隐藏。
7. 导出最终图片。
8. 图片默认不永久保存，处理任务完成后自动清理。

## 2. 产品边界

### MVP 包含

- JPG、PNG、WebP 图片上传。
- 最大图片大小：10 MB。
- 一张图片最多处理 30 张人脸。
- 人脸检测：SCRFD 或 YOLOv8-face 二选一，首版优先使用易部署的 YOLOv8-face。
- 表情类别：`happy`、`sad`、`angry`、`surprise`、`fear`、`disgust`、`neutral`。
- 预设 emonjj 素材包。
- 基于人脸框的贴纸定位。
- 单个贴纸编辑。
- 前端 Canvas 合成和 PNG 导出。
- 桌面端和移动端响应式布局。

### MVP 不包含

- 用户注册、登录和历史作品库。
- 永久保存原图或成品图。
- 视频、动图和摄像头实时处理。
- 无限图片批处理。
- 保证表情识别正确的承诺。
- 首版内置大型生成式模型。

## 3. 用户流程

```text
进入 emoji 子域名
  ↓
上传或拖入群像图片
  ↓
显示原图预览与处理提示
  ↓
调用 Hugging Face Spaces 推理接口
  ↓
返回人脸框、关键点、表情类别和置信度
  ↓
用户点击“一键添加 emonjj”
  ↓
前端按表情映射叠加贴纸
  ↓
用户点击某个人脸进行单独替换或调整
  ↓
导出 PNG
  ↓
清理临时任务与上传文件
```

## 4. 页面设计

### 4.1 首页 / 上传页

页面目标是让用户在 5 秒内理解用途并开始操作。

页面组成：

- 顶部品牌名：`AI Emonjj`。
- 一句说明：`给群像图片里的每个人加上合适的 emonjj`。
- 主上传区域：支持点击选择和拖拽上传。
- 示例图片入口：使用项目内置的低分辨率示例图，不上传到第三方。
- 隐私提示：`图片只用于本次处理，任务结束后自动清理`。
- 开始按钮：上传成功后显示 `开始识别人脸`。

状态：

- 空状态：显示上传引导。
- 上传中：显示文件名、进度和取消按钮。
- 格式错误：提示支持的格式。
- 大小错误：提示最大 10 MB。

### 4.2 检测结果页

页面分为预览区和控制区。

预览区：

- 使用 Canvas 显示原图。
- 人脸框使用半透明边框标识。
- 每张人脸显示序号和表情标签。
- 置信度低于阈值时显示 `需要确认`，不直接覆盖用户选择。
- 支持缩放、适应窗口和恢复原始比例。

控制区：

- 人脸数量。
- 表情识别状态。
- 主按钮：`一键添加 emonjj`。
- 次按钮：`重新识别`。
- 重新上传入口。

### 4.3 编辑页

用户点击某个人脸后，打开该人脸的编辑面板。

编辑能力：

- emonjj 素材网格：按 `全部`、`开心`、`悲伤`、`生气`、`惊讶`、`中性` 分类。
- 当前素材高亮。
- 缩放滑杆：默认 100%，范围 50%～200%。
- 旋转滑杆：默认 0°，范围 -30°～30°。
- 水平偏移和垂直偏移微调按钮。
- `隐藏这个 emonjj`。
- `恢复系统推荐`。
- `应用到所有相同表情`，默认关闭。

### 4.4 导出页

- 显示最终合成预览。
- 导出格式：首版 PNG，后续可增加 JPG。
- 导出按钮：`下载图片`。
- 导出失败时保留编辑状态并提供重试。
- 导出完成后显示隐私提示：临时任务将被清理。

## 5. emonjj 素材系统

素材必须放在前端可读取的版本化目录中，例如：

```text
public/emonjj/
  default.png
  happy-01.png
  happy-02.png
  sad-01.png
  angry-01.png
  surprise-01.png
  neutral-01.png
```

每个素材通过清单文件描述：

```json
{
  "id": "happy-01",
  "label": "开心脸",
  "emotion": "happy",
  "src": "/emonjj/happy-01.png",
  "anchor": "center",
  "defaultScale": 1.15
}
```

表情到素材的默认映射：

```json
{
  "happy": "happy-01",
  "sad": "sad-01",
  "angry": "angry-01",
  "surprise": "surprise-01",
  "fear": "surprise-01",
  "disgust": "angry-01",
  "neutral": "neutral-01"
}
```

素材需要满足：透明背景、统一视觉风格、可商用或项目作者拥有授权。不得直接复制没有明确许可的第三方贴纸包。

## 6. 技术架构

```text
GitHub Pages
  └── 静态前端
      ├── 上传与预览
      ├── Canvas 合成
      ├── emonjj 素材
      └── 导出图片

Hugging Face Spaces
  └── 免费推理服务
      ├── 人脸检测
      ├── 表情裁剪与分类
      └── 返回 JSON 结果
```

前端建议：

- Vite + React + TypeScript。
- Canvas 2D 或 Konva.js 负责图层编辑。
- 原图和贴纸均使用前端内存对象，不写入永久存储。
- 通过 HTTPS 调用 Hugging Face Spaces API。

后端建议：

- Hugging Face Spaces + Gradio 或 FastAPI。
- Python 3.11。
- 人脸检测模型：YOLOv8-face；如果群像小脸效果不足，替换为 SCRFD。
- 表情模型：轻量 MobileNet/ResNet 表情分类模型或 DeepFace 的表情模块。
- 返回人脸框、关键点、表情类别、置信度。

## 7. API 约定

### `POST /predict`

请求：`multipart/form-data`

- `image`: 图片文件。

响应：

```json
{
  "image": { "width": 1600, "height": 900 },
  "faces": [
    {
      "id": "face-001",
      "bbox": { "x": 420, "y": 180, "width": 120, "height": 120 },
      "landmarks": {
        "leftEye": [455, 220],
        "rightEye": [500, 220],
        "nose": [478, 250],
        "mouth": [478, 275]
      },
      "emotion": "happy",
      "confidence": 0.87
    }
  ],
  "warnings": []
}
```

错误响应必须包含稳定的 `code` 和用户可读的 `message`，例如：`INVALID_IMAGE`、`IMAGE_TOO_LARGE`、`MODEL_TIMEOUT`、`SPACE_SLEEPING`。

## 8. 前端合成规则

贴纸默认位置由人脸框计算：

```text
贴纸中心 = 人脸框中心
贴纸宽度 = 人脸框宽度 × defaultScale
贴纸高度 = 按素材原始宽高比计算
```

如果检测到关键点，则优先使用双眼中心与嘴部位置估计脸部旋转和贴纸锚点。用户手动调整后，保存覆盖系统默认值。

每个图层的数据结构：

```ts
type EmojiLayer = {
  faceId: string;
  assetId: string;
  visible: boolean;
  x: number;
  y: number;
  scale: number;
  rotation: number;
  source: "recommended" | "manual" | "generated";
};
```

## 9. 免费与资源限制

免费定位必须明确以下限制：

- GitHub Pages 只托管静态页面，不运行 Python 或 YOLO。
- Hugging Face Spaces 免费实例可能休眠，首次请求会慢。
- 免费 CPU 推理不适合高并发和大批量处理。
- 不保证任何模型对所有图片都准确。
- AI 生成 emonjj 只能作为后续实验能力，不作为 MVP 的核心承诺。
- 应在前端显示“模型推测”而不是“确定识别”。
- 对请求设置客户端超时、重试次数和友好错误提示。

建议默认限制：

- 图片最大 10 MB。
- 最大分辨率 4096×4096，超出时前端等比缩放。
- 单次最多 30 张人脸。
- 单次请求超时 60 秒。
- 失败重试最多 2 次。

## 10. 隐私与安全

- 首版无需账号。
- 前端不保存历史作品。
- 不保存原始图片和推理结果到数据库。
- Hugging Face 服务只在处理期间接收图片，并在任务结束后释放临时文件。
- 页面明确说明图片会发送到 Hugging Face Spaces 进行处理。
- 禁止上传违法、侵权或不适合公开处理的图片。
- API 端限制文件类型、文件大小和请求频率。
- 不在日志中记录原图、Base64 内容或人脸图片。

## 11. 部署步骤

### GitHub Pages

1. 在 GitHub 创建前端仓库。
2. 配置 Vite 生产构建。
3. 使用 GitHub Actions 构建并发布 `dist`。
4. 在仓库 Pages 设置中启用 GitHub Actions 部署。
5. 配置自定义域名，例如 `emoji.example.com`。
6. 在 DNS 中为子域名添加 GitHub Pages 要求的 CNAME 记录。

### Hugging Face Spaces

1. 创建公开或受限的 Space。
2. 选择 Gradio 或 Docker SDK。
3. 安装模型和推理依赖。
4. 提供 `/predict` 接口。
5. 配置 CORS，只允许 AI Emonjj 子域名调用。
6. 使用一张多人脸测试图验证坐标、关键点和表情 JSON。
7. 将 Space API 地址写入前端环境变量。

## 12. 验收标准

- 用户无需登录即可上传图片。
- JPG、PNG、WebP 能正常预览。
- 上传错误会显示明确原因。
- 正常群像图可以返回多个人脸结果。
- 每个人脸都有稳定唯一 ID。
- 表情置信度低时会提示用户确认。
- 一键添加后，所有可识别人脸都有对应 emonjj。
- 单击任意 emonjj 可以单独替换，不影响其他图层。
- 缩放、旋转、隐藏和恢复推荐有效。
- 导出图片尺寸与预览一致。
- 导出后的图片不包含调试框和内部 ID。
- 未检测到人脸时仍允许用户重新上传或选择示例图。
- Hugging Face 休眠或超时时，页面显示可理解的重试提示。
- 页面在移动端宽度 375px 下仍可完成上传和导出。

## 13. 后续迭代

### 第二阶段

- 追加更多 emonjj 素材。
- 支持用户上传自定义贴纸。
- 增加 JPG 导出和质量选择。
- 增加局部重识别。
- 优化小脸检测和侧脸检测。

### 第三阶段

- 接入 AI 生成 emonjj 的可选接口。
- 允许用户输入风格提示词。
- 为每个人脸生成多个候选贴纸。
- 增加素材收藏和本地配置导入导出。

### 不建议过早加入

- 登录和云端历史库。
- 社交分享平台。
- 视频处理。
- 复杂时间线编辑器。
- 无限批量任务。

## 15. 关键决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 前端托管 | GitHub Pages | 已有博客基础设施且免费 |
| 模型托管 | Hugging Face Spaces | 可免费部署开源模型，适合 MVP |
| 核心素材 | 固定 emonjj 优先 | 速度快、效果稳定、可手动修正 |
| AI 生成 | 后续可插拔 | 免费资源无法保证稳定的生成式推理 |
| 图片保存 | 不永久保存 | 降低隐私、存储和合规成本 |
| 表情结果 | 作为推荐 | 模型存在误判，必须允许用户覆盖 |
